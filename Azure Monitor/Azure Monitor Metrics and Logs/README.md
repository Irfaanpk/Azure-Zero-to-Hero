# 15.2 Azure Monitor Metrics and Logs

## Azure Monitor Metrics

**Azure Monitor Metrics** are numerical values collected at regular intervals to measure the performance and health of Azure resources.

Examples:

- CPU percentage
- Network traffic
- Disk operations
- Request count
- Storage capacity
- Availability

```text
Azure Resource
      │
      ▼
   Metrics
      │
      ▼
Azure Monitor
      │
      ▼
Metrics Explorer
```

---

# Metric Data

A metric is usually represented as a time-series value.

Example:

```text
Time       CPU Usage
10:00      25%
10:05      40%
10:10      65%
10:15      85%
```

This allows you to identify performance trends over time.

---

# Metrics Explorer

**Metrics Explorer** allows you to view and analyze metrics for Azure resources.

You can:

- Select a resource
- Select a metric
- Choose a time range
- Apply aggregation
- Filter or split data
- Create charts

Example:

```text
VM
 │
 ▼
Metrics Explorer
 │
 ▼
CPU Percentage
 │
 ▼
Time-Series Chart
```

---

# Metric Aggregation

Metrics can be aggregated over a selected time period.

Common aggregations include:

| Aggregation | Meaning |
|---|---|
| Average | Average value |
| Minimum | Lowest value |
| Maximum | Highest value |
| Total | Sum of values |
| Count | Number of values |

Example:

```text
CPU Values:

40%
60%
80%

Average = 60%
Maximum = 80%
Minimum = 40%
```

---

# Dimensions

Some metrics contain **dimensions** that allow you to break down metric data.

Example:

```text
Network Traffic
      │
      ├── Interface 1
      ├── Interface 2
      └── Interface 3
```

Dimensions allow you to analyze a metric for specific components or categories.

---

# Metrics vs Logs

| Metrics | Logs |
|---|---|
| Numerical measurements | Detailed records |
| Time-series data | Event and diagnostic data |
| Good for performance monitoring | Good for investigation |
| Fast analysis | Detailed querying |
| Viewed using Metrics Explorer | Queried using Log Analytics |
| Example: CPU = 85% | Example: Application error |

---

# Azure Monitor Logs

**Azure Monitor Logs** provide detailed information collected from Azure resources, applications, and other sources.

Logs can contain:

- Events
- Errors
- Warnings
- Resource activity
- Application information
- Operating system information

```text
Resources
    │
    ▼
Log Data
    │
    ▼
Log Analytics Workspace
    │
    ▼
KQL Queries
```

---

# Log Analytics Workspace

A **Log Analytics workspace** is a centralized environment for storing and querying log data.

Example:

```text
VM ──────────┐
             │
Storage ─────┤
             ▼
       Log Analytics
         Workspace
             │
             ▼
            KQL
```

Multiple Azure resources can send their logs to the same workspace.

---

# Types of Logs

Important Azure monitoring logs include:

### Activity Log

Records subscription-level management operations.

Examples:

```text
Create VM
Delete Storage Account
Modify NSG
Assign RBAC Role
```

### Resource Logs

Provide detailed information generated by supported Azure resources.

Examples:

```text
Storage Account Logs
Application Gateway Logs
Key Vault Logs
```

### Guest OS Logs

Logs generated inside an operating system running on a VM.

Examples:

```text
Windows Event Logs
Linux Syslog
```

Guest OS data collection can be configured using **Azure Monitor Agent and Data Collection Rules**, covered in **15.5**.

---

# Activity Log vs Resource Logs

| Activity Log | Resource Logs |
|---|---|
| Subscription-level | Resource-level |
| Management operations | Resource operations |
| Automatically collected | Must be configured for collection |
| Example: Delete VM | Example: Storage request |
| Azure control-plane activity | Resource-specific diagnostic information |

---

# Log Analytics

Log Analytics allows administrators to query and analyze logs stored in a Log Analytics workspace.

Example:

```text
Log Analytics Workspace
          │
          ▼
      KQL Query
          │
          ▼
     Query Results
```

KQL is covered in detail in **15.3**.

---

# Metrics and Logs Together

Metrics and logs can be used together for troubleshooting.

Example:

```text
VM CPU = 95%
      │
      ▼
Metric indicates performance issue
      │
      ▼
Query VM/Application Logs
      │
      ▼
Find the cause
```

Metrics help identify **that something is wrong**.

Logs help investigate **why it is wrong**.

---

# Example: Troubleshooting a VM

Suppose a VM is running slowly.

### Step 1 — Check Metrics

```text
CPU → 95%
Disk → High
Network → Normal
```

The metrics indicate high CPU utilization.

### Step 2 — Check Logs

Query the logs to determine which process or event may be responsible.

```text
Metrics
   ↓
Identify Problem
   ↓
Logs
   ↓
Investigate Cause
```

# Key Points

- Azure Monitor Metrics are numerical measurements of resource performance.
- Metrics are generally time-series data.
- Metrics Explorer is used to visualize and analyze metrics.
- Metrics support aggregations such as Average, Minimum, Maximum, Total, and Count.
- Dimensions can be used to break down metric data.
- Azure Monitor Logs contain detailed event and diagnostic information.
- Log Analytics workspaces provide centralized storage and querying for logs.
- Activity Log records subscription-level management operations.
- Resource logs provide resource-specific diagnostic information.
- Guest OS logs provide operating-system-level information.
- Metrics help identify performance problems.
- Logs help investigate the cause of problems.
- Metrics and logs can be used together for effective troubleshooting.
