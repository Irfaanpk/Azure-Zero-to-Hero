# 15.4 Diagnostic Settings

## What are Diagnostic Settings?

**Diagnostic Settings** are used to configure the collection and routing of monitoring data from Azure resources.

They allow you to send resource logs and metrics to different destinations for storage, analysis, or further processing.

```text
Azure Resource
      │
      ▼
Diagnostic Settings
      │
      ├── Log Analytics Workspace
      ├── Storage Account
      └── Event Hubs
```

---

# Why Use Diagnostic Settings?

Diagnostic Settings are useful for:

- Collecting resource logs
- Sending logs to Log Analytics
- Archiving logs in Storage Accounts
- Streaming logs to Event Hubs
- Centralized monitoring
- Troubleshooting
- Compliance and auditing

---

# Diagnostic Settings vs Activity Log

| Diagnostic Settings | Activity Log |
|---|---|
| Configuration used to route monitoring data | Records subscription-level management activity |
| Used mainly for resource logs and metrics | Automatically collected |
| Can send data to different destinations | Can be exported using diagnostic settings |
| Configured per supported resource | Available at subscription level |

---

# Resource Logs

Resource logs provide detailed information generated by an Azure resource.

Examples:

```text
Storage Account
      ↓
Resource Logs

Application Gateway
      ↓
Resource Logs

Key Vault
      ↓
Resource Logs
```

Resource logs are not automatically sent to every destination. Diagnostic settings are used to configure where the data should go.

---

# Metrics

Diagnostic settings can also route supported platform metrics to a destination.

Example:

```text
Azure Resource
      │
      ├── Resource Logs
      │
      └── Platform Metrics
              │
              ▼
      Diagnostic Settings
```

The available categories depend on the Azure resource.

---

# Diagnostic Setting Destinations

Diagnostic data can be sent to supported destinations such as:

### Log Analytics Workspace

Used for:

- Log querying
- Troubleshooting
- KQL analysis
- Centralized monitoring
- Alerting

```text
Azure Resource
      ↓
Diagnostic Setting
      ↓
Log Analytics Workspace
      ↓
KQL
```

---

### Storage Account

Used to archive monitoring data.

```text
Azure Resource
      ↓
Diagnostic Setting
      ↓
Storage Account
      ↓
Long-Term Storage
```

This can be useful when logs need to be retained for longer periods.

---

### Event Hubs

Event Hubs can be used to stream monitoring data to external systems.

```text
Azure Resource
      ↓
Diagnostic Setting
      ↓
Event Hubs
      ↓
External Monitoring System
```

---

# One Resource Can Have Multiple Destinations

A diagnostic setting can be configured to send monitoring data to supported destinations.

Example:

```text
                    Azure Resource
                         │
                         ▼
                 Diagnostic Setting
                    /      |      \
                   /       |       \
                  ▼        ▼        ▼
           Log Analytics Storage  Event Hubs
             Workspace   Account
```

---

# Diagnostic Setting Configuration

A diagnostic setting generally contains:

```text
Diagnostic Setting
       │
       ├── Categories
       │
       └── Destinations
```

You select which monitoring categories should be collected and where they should be sent.

---

# Log Categories

Different Azure resources expose different diagnostic log categories.

For example, a resource might provide categories such as:

```text
Audit Logs
Request Logs
Error Logs
Operational Logs
```

The available categories depend on the specific Azure resource.

---

# Diagnostic Settings and Log Analytics

A common architecture is to send resource logs to a centralized Log Analytics workspace.

```text
VM ───────────┐
              │
Storage ──────┤
              ▼
Application ──┤
              │
              ▼
       Log Analytics
          Workspace
              │
              ▼
             KQL
```

This allows administrators to query logs from multiple resources in one place.

---

# Diagnostic Settings and Storage

A Storage Account can be used as a destination for monitoring data.

```text
Azure Resource
      │
      ▼
Diagnostic Setting
      │
      ▼
Storage Account
      │
      ▼
Archived Monitoring Data
```

This is useful when monitoring data needs to be retained for archival purposes.

---

# Diagnostic Settings and Event Hubs

Event Hubs can be used when monitoring data needs to be streamed to another system.

```text
Azure Resource
      │
      ▼
Diagnostic Setting
      │
      ▼
Event Hubs
      │
      ▼
External System
```

---

# Diagnostic Settings for Activity Log

Azure Activity Log can also be exported using Diagnostic Settings.

Example:

```text
Subscription
      │
      ▼
Activity Log
      │
      ▼
Diagnostic Setting
      │
      ├── Log Analytics
      ├── Storage
      └── Event Hubs
```

This allows Activity Log data to be retained or analyzed beyond its default retention period.

---

# Diagnostic Settings vs Log Analytics

These two concepts are related but different.

```text
Diagnostic Settings
        ↓
"Where should monitoring data go?"

Log Analytics
        ↓
"Where can I store and query log data?"
```

Example:

```text
Storage Account
      ↓
Diagnostic Setting
      ↓
Log Analytics Workspace
      ↓
KQL
```

# Practical Lab

## Lab: Configure Diagnostic Settings for a Storage Account

### Objective

Configure Diagnostic Settings for an Azure Storage Account and send resource logs to a Log Analytics workspace.

---

## Step 1: Create a Log Analytics Workspace

1. Open **Azure Portal**.
2. Search for **Log Analytics workspaces**.
3. Select **Create**.
4. Select your subscription.
5. Select or create a resource group.
6. Enter a workspace name.

Example:

```text
law-diagnostic-demo
```

7. Select the appropriate region.
8. Select **Review + create**.
9. Select **Create**.

---

## Step 2: Open a Storage Account

1. Open **Azure Portal**.
2. Search for **Storage accounts**.
3. Select an existing test Storage Account.

---

## Step 3: Open Diagnostic Settings

Go to:

```text
Storage Account
    ↓
Monitoring
    ↓
Diagnostic settings
```

Select:

```text
+ Add diagnostic setting
```

---

## Step 4: Configure Categories

Enter a name:

```text
storage-diagnostics
```

Select the required resource log categories.

For the lab, select the available categories you want to monitor.

Also select supported metrics if required.

---

## Step 5: Select Destination

Select:

```text
Send to Log Analytics workspace
```

Choose:

```text
Subscription:
<YOUR SUBSCRIPTION>

Log Analytics Workspace:
law-diagnostic-demo
```

---

## Step 6: Save the Configuration

Select **Save**.

The configuration becomes:

```text
Storage Account
      │
      ▼
Diagnostic Setting
      │
      ▼
Log Analytics Workspace
```

---

## Step 7: Generate Storage Activity

Perform some operations against the Storage Account.

For example:

```text
Upload a blob
Download a blob
Create a container
Delete a test blob
```

---

## Step 8: Query the Logs

Open:

```text
Log Analytics Workspace
      ↓
Logs
```

Use the available storage resource log table for the configured diagnostic categories.

Example:

```kql
StorageBlobLogs
| take 10
```

Review the collected storage activity.

---

# Key Points

- Diagnostic Settings configure how monitoring data is collected and routed.
- They are commonly used for Azure resource logs and supported platform metrics.
- Resource log categories depend on the Azure resource.
- Data can be sent to a Log Analytics workspace.
- Data can be archived in a Storage Account.
- Data can be streamed through Event Hubs.
- Activity Log can also be exported using Diagnostic Settings.
- Diagnostic Settings determine **where monitoring data goes**.
- Log Analytics provides a place to **store and query logs**.
- Diagnostic Settings and Log Analytics work together for centralized monitoring and troubleshooting.
